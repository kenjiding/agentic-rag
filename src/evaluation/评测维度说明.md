# 评测系统维度说明

本文档说明评测系统中四个核心维度的含义、评测内容与计算方法。

---

## 一、任务完成度（Task Completion）

### 评测什么

评估 **Agent 是否按用例预期完成了业务目标**，即「结果对不对」。

- **预期结果验证**：用例中定义的 `expected_outcomes` 是否达成  
- **里程碑完成**：多步骤任务中，各里程碑（`milestones`）是否按条件达成  
- **Agent/意图匹配**：实际调用的 Agent、识别的意图是否与用例期望一致  

### 预期结果类型（OutcomeType）

| 类型 | 说明 | 验证方式 |
|------|------|----------|
| `state_match` | 状态字段匹配 | 最终状态中某字段等于期望值 |
| `response_contains` | 响应包含内容 | 最终回复文本包含期望关键词/片段 |
| `agent_called` | 特定 Agent 被调用 | 执行轨迹中出现期望的 Agent |
| `tool_called` | 特定工具被调用 | 执行轨迹中出现期望的工具调用 |
| `milestone_reached` | 达成里程碑 | 按里程碑条件检查轨迹或状态 |

### 分数计算

- **预期结果**：约 60% 权重，对各 `expected_outcomes` 的得分按权重加权  
- **里程碑**：约 30% 权重，对已定义里程碑的达成情况加权  
- **Agent/意图匹配**：约 10% 权重，作为加分项  

最终 **任务完成度** 为 0～1，高于配置的 `success_threshold` 时，该用例在「任务完成」维度判为通过。

### 数据来源

- 用例中的 `expected_outcomes`、`milestones`、`expected_agent`、`expected_intent`  
- 运行得到的 `execution_trace`（action_audit）、`final_state`

## 二、轨迹质量（Trajectory Quality）

### 评测什么

评估 **多步执行过程的质量**：工具选得对不对、顺序对不对、是否冗长，即「过程好不好」。

- **工具选择准确率（Node F1）**：实际调用的工具集合与期望工具集合的重合度（Precision/Recall/F1）  
- **工具顺序正确率（Edge F1）**：相邻工具对的顺序是否与期望一致  
- **步骤效率**：实际步数与「期望步数」的比值，避免多余步骤  
- **序列相似度**：实际工具调用序列与期望序列的归一化编辑距离（越相似分数越高）  

### 核心指标

| 指标 | 说明 |
|------|------|
| **Node F1** | 工具集合层面的准确率/召回率/F1，衡量「有没有用对工具」 |
| **Edge F1** | 相邻工具对的匹配程度，衡量「调用顺序是否正确」 |
| **Efficiency** | min(期望步数/实际步数, 1.0)，步数越少、越接近期望则越高 |
| **Edit Distance** | 实际序列与期望序列的归一化编辑距离，转换为相似度参与综合分 |

### 分数计算

轨迹质量综合分由以下权重合成（具体权重以代码为准，此处为典型值）：

- **Node F1**：约 40%（工具选择最重要）  
- **Edge F1**：约 30%（顺序其次）  
- **Efficiency**：约 20%  
- **编辑距离对应的相似度**：约 10%  

最终 **轨迹质量** 为 0～1。若用例定义了 `expected_tool_calls`，会优先与之对比；未定义时部分子项可能退化为默认或跳过。

### 数据来源

- 用例中的 `expected_tool_calls`  
- 从 `execution_trace` 中解析出的实际工具调用序列

## 三、工具准确率（Tool Accuracy）

### 评测什么

在实现上，**工具准确率** 与轨迹质量中的 **Node F1** 一致：衡量 **实际调用的工具集合** 与 **期望工具集合** 的匹配程度。

- 从 `execution_trace` 中提取所有 `tool_called`（或等价）事件，得到实际工具序列  
- 与用例的 `expected_tool_calls` 做集合/序列对比  
- 计算 Precision、Recall、F1，其中 **F1 作为工具准确率** 写入报告  

### 与轨迹质量的区别

- **轨迹质量**：综合 Node F1、Edge F1、效率、编辑距离等多个子项，反映「整条轨迹」的质量。  
- **工具准确率**：仅取 Node F1，单独呈现「工具选对与否」这一维度的分数，便于快速看「有没有用错/漏用工具」。  

### 分数含义

- **1.0**：实际调用的工具与期望完全一致（集合层面）  
- **0～1 之间**：部分一致，存在多调、少调或调错工具  
- **0**：完全未按期望使用工具（或期望为空而实际有调用等边界情况）  

当 `expected_tool_calls` 未定义时，部分逻辑会给出默认值（例如无期望则可能记为满分或跳过），以代码与配置为准。

## 四、合规性（Policy Compliance）

### 评测什么

评估 **是否违反安全与业务策略**，即「有没有做不该做的事」。  
思路对应 ST-WebAgentBench 的 **Completion under Policy (CuP)**：在合规前提下看任务完成情况。

- **策略规则（PolicyRule）**：在配置或代码中定义多条规则，每条包含规则 ID、描述、严重程度、检测类型与检测配置。  
- **违规检测**：对每条执行轨迹事件（及可选地对最终状态）做检测，命中规则则记为一次违规。  
- **合规分数**：根据违规次数与严重程度扣分，得到 0～1 的 **策略合规分数**。  

### 检测类型（detection_type）

| 类型 | 说明 |
|------|------|
| `event_pattern` | 按事件字段匹配（如 event、node、tool_name 等），命中即违规 |
| `tool_restriction` | 限制禁止调用的工具，若轨迹中出现配置的 `restricted_tools` 则违规 |
| `state_condition` | 对最终状态做条件判断（如某字段 equals/contains 等），满足则违规 |

### 常见策略示例（来自配置/代码）

- **未授权订单**：禁止在未授权情况下下单（如 event_pattern 匹配下单动作）  
- **PII 保护**：禁止在日志或对外输出中泄露敏感信息（如 event_pattern 匹配敏感字段）  
- **危险工具**：禁止调用高危工具（tool_restriction）  
- **限流合规**：调用频率/方式符合限流策略（event_pattern）  

### 分数计算

- **无违规**：合规分数 = 1.0  
- **有违规**：按严重程度（critical / high / medium / low）加权扣分，最终合规分数在 0～1 之间  

汇总报告中的「合规性」即所有用例的 **策略合规分数** 的统计（如平均、通过率等）。

### 数据来源

- 策略定义：`config/evaluation.yaml` 中的 `safety.policies` 或代码中的 `PolicyRule`  
- 检测对象：`execution_trace` 中各事件，以及可选的 `final_state`

## 维度与评测器对应关系

| 报告中的维度 | 评测器 | 主要输出字段 |
|--------------|--------|--------------|
| 任务完成度 | TaskCompletionEvaluator | task_completion_score |
| 轨迹质量 | TrajectoryEvaluator | trajectory_quality_score |
| 工具准确率 | TrajectoryEvaluator（Node F1） | tool_accuracy_score |
| 合规性 | SafetyEvaluator | policy_compliance_score |

组合评测时，由 **CompositeEvaluator** 依次调用上述评测器，再汇总为单用例的总体结果与报告中的汇总统计。

---

## 如何提升各维度分数

- **任务完成度**：优化意图识别与路由、Agent 回复内容与状态更新，使实际结果和里程碑满足用例中的 `expected_outcomes` 与 `milestones`。  
- **轨迹质量**：优化规划与工具选择逻辑，使工具调用序列、顺序和步数尽量符合 `expected_tool_calls` 与业务预期。  
- **工具准确率**：同轨迹质量，重点保证「用对工具、不漏不滥」。  
- **合规性**：在设计与实现中遵守已配置的 PolicyRule，避免触发 event_pattern、tool_restriction、state_condition 等检测条件。
